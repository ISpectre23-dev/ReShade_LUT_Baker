# Monster Hunter Wilds LUT export profile

This writer targets the single-mip **33³ RGBA16F** profile observed in map and
event LUTs from Wilds **1.42.0.2**. The supplied investigation examined eleven
grading textures and one separate engine-neutral texture. The neutral is 32³
RGBA8 with a different pitch and control byte. This writer does not generate
that neutral profile or treat Rise TEX28 as compatible.

Local research textures were inspected read-only. No game asset, executable,
dump or runtime DLL is copied into this repository or the release.

## Container

All multi-byte fields are little-endian. The first 56 bytes reproduce the
observed RGBA16F header exactly. Unknown control bytes are not reinterpreted.

| Offset | Field | Value |
| --- | --- | --- |
| 0 | Signature | `TEX\0` |
| 4 | Version, uint32 | 241106027 |
| 8 / 10 / 12 | Width / height / depth, uint16 | 33 / 33 / 33 |
| 14 / 15 | Image count / mip-header size | 1 / 16 |
| 16 | DXGI format, uint32 | 10, `R16G16B16A16_FLOAT` |
| 20 | Swizzle control, int32 | -1 |
| 24 | Cubemap marker, uint32 | 0 |
| 28–39 | Control bytes | `00 07 00 00`, then eight zeros |
| 40 | Mip offset, uint64 | 56, points to the compressed image header |
| 48 | Row pitch, uint32 | 512 bytes |
| 52 | Per-depth-slice size, uint32 | 16,896 bytes |
| 56 | Compressed image size, uint32 | Exact size of the GDeflate stream |
| 60 | Image offset, uint32 | 0 |
| 64 | Image data | GDeflate stream, starts with `04 FB` |

There are 35,937 nodes. Each row stores 33 eight-byte RGBA16F pixels, then
248 zero padding bytes. The decoded payload is **557,568 bytes**, not the
per-slice size in the mip header. File size varies with compression.

```text
sample_index = (blue * 33 + green) * 33 + red
payload_offset = (blue * 33 + green) * 512 + red * 8
pixel = little-endian half(R), half(G), half(B), half(1.0)
```

The baker evaluates a 33³ identity lattice directly. Its existing layout helper
flattens it into a 297×121 floating-point target. It does not bake at 64³ and
resample. Shader output alpha is ignored; stored alpha is always one.

## Precision and validation

Conversion uses the existing binary32-to-binary16 round-to-nearest-even helper.
Finite RGB in **[-65504, 65504]** is accepted, including negatives and values
above one. Non-finite values and values outside that range fail before writing.
No clamping, gamma conversion, dithering or integer intermediate is applied.
Maximum, mean and RMS rounding error are measured against the actual float
input, independently of the GPU identity error.

GDeflate is lossless compression. The codec is built from pinned
[Microsoft reference sources](https://github.com/microsoft/DirectStorage/tree/c53f1499d5f67a61b69a1a348d22dcd2b4cb4ede/GDeflate)
and their NVIDIA libdeflate submodule. It runs on the existing CPU export
worker. The serializer validates the resulting container, bounds every tile,
decodes with exact output-size limits, and compares all decoded bytes with the
prepared payload before allowing the atomic, non-overwriting write.

Tests independently specify the header and verify every node, alpha value,
row-padding byte and half-precision value. A 33³ identity uses steps of 1/32,
which are exactly representable in binary16: its offline numeric maximum,
mean and RMS error are all **zero**. Asymmetric fixtures check axes, channels,
negative and super-white output, and binary16 rounding. Fixtures are CPU writer
tests, not extra grading shaders or recommended presets.

The optional Python `--codec` path uses Microsoft's `IDStorageCompressionCodec`
from a caller-specified trusted DLL as an independent decoder. The add-on never
loads that DLL. See [BUILDING.md](../BUILDING.md) for validation commands.

## Color domain and release status

This is **numeric export**, not an automatic conversion from display grading to
Wilds' native grading stage. The examined
[SDR shader reference](https://github.com/MohannedElfatih/renodx/blob/f9fc9c0a04eace26be8b387837dff42e165e4ae4/src/games/mhwilds/postprocess_sdr_0xF06499FE.ps_6_6.hlsl)
and [HDR shader reference](https://github.com/MohannedElfatih/renodx/blob/f9fc9c0a04eace26be8b387837dff42e165e4ae4/src/games/mhwilds/postprocess_0x441E59B3.ps_6_6.hlsl)
encode a logarithmic coordinate before sampling and decode the result afterward.
These are reconstructed third-party shaders, not a verified capture of the
installed executable. No guessed inverse tonemapping or LogC conversion is
added to the exporter.

Do not infer visual equivalence from valid TEX bytes, zero numeric identity
error, or a working Rise export. Wilds exports have been reported working
in-game. Visual equivalence across presets and SDR/HDR still requires separate
testing. Use a compatible Wilds LUT manager and keep engine settings stable.
The manager must support this exact profile and replace participating slots
without unintended double grading.
The baker does not install the file, replace game LUTs or implement that manager.

Native format evidence is corroborated by the
[RE-Mesh-Editor TEX parser](https://github.com/NSACloud/RE-Mesh-Editor/blob/main/modules/tex/file_re_tex.py).
The DXGI value is defined by Microsoft's
[DXGI format enum](https://learn.microsoft.com/en-us/windows/win32/api/dxgiformat/ne-dxgiformat-dxgi_format).
